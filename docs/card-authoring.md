# Card Authoring Guide

This guide explains how to add, update, remove, and translate cards without editing code. The CLI manages data in `src/data/store.json`.

## Data model overview

## Legal and naming guidelines
- Do not use trademarked names from the original game in IDs, type names, activities, or card text.
- Avoid brand names or copyrighted phrases in prompts and answers.
- Use neutral, descriptive names (e.g. `blue_dibu_ciego`) and original activity text.
- Keep category IDs as colors only (`blue`, `red`, `green`, `yellow`).
- When in doubt, rephrase to generic wording and update IDs to match.

### Category
A category is a color lane. Categories are minimal and do not contain trademarked names.

Required fields:
- `id` (string): e.g. `blue`, `red`, `green`, `yellow`.
- `name` (localized string): e.g. `{ "es": "Azul", "en": "Blue" }`.
- `colorHex` (string): hex color like `#1e88e5`.

### Card type
A card type belongs to a category and stores the shared activity text once.

Required fields:
- `id` (string): stable slug, e.g. `blue_dibu_ciego`.
- `categoryId` (string): category id, e.g. `blue`.
- `name` (localized string): display name of the type.
- `activity` (localized string): shared activity instructions.
- `mode` (string): `team` or `all-play`.

### Card
A card is the variable challenge. It always has two sides:
- Front: `content.blocks`.
- Back: `content.answer`.

Required fields:
- `id` (string): stable and unique.
- `typeId` (string): must exist in `cardTypes`.
- `groups` (string[]): tags for sets (e.g. `colombia`, `pop-2024`).
- `languages` (string[]): list of languages present in `content`.
- `createdAt` (string): `YYYY-MM-DD`.
- `content` (object): per-language payload.

Card content structure:
- `content.es.blocks`: list of blocks shown on the front.
- `content.es.answer`: back side answer.

Blocks:
- `label` (string): e.g. `PISTA`, `PREGUNTA`.
- `text` (string): a single line.
- `list` (string[]): for options or lists.

## Store location
All data lives in:
- `src/data/store.json`

Do not edit this file manually. Use the CLI.

## CLI usage

### List cards
```bash
pnpm cards:list
pnpm cards:list --category blue
pnpm cards:list --type red_elige_una
pnpm cards:list --group colombia --group 2020s
pnpm cards:list --language es
pnpm cards:list --missing-language en
```

### Add a card
1) Create a JSON file, for example `tmp/new-card.json`:
```json
{
  "id": "blue_dibu_ciego_010",
  "typeId": "blue_dibu_ciego",
  "groups": ["colombia", "urbano"],
  "languages": ["es"],
  "createdAt": "2025-01-10",
  "content": {
    "es": {
      "blocks": [{ "label": "PISTA", "text": "LUGAR" }],
      "answer": "Metro de Medellin"
    }
  }
}
```

2) Add it:
```bash
pnpm cards:add --input tmp/new-card.json
```

If `createdAt` is omitted, the CLI sets it to today.

### Update a card
Use a full replacement or merge.

Replace:
```bash
pnpm cards:update --id blue_dibu_ciego_010 --input tmp/new-card.json
```

Merge (only changes provided fields):
```bash
pnpm cards:update --id blue_dibu_ciego_010 --input tmp/patch.json --merge
```

### Remove a card
```bash
pnpm cards:remove --id blue_dibu_ciego_010
```

### Missing translations
To help translators, list cards missing a language:
```bash
pnpm cards:missing --language en
```

## Managing card types

### List types
```bash
pnpm types:list
```

### Add a type
Create `tmp/new-type.json`:
```json
{
  "id": "blue_sombras",
  "categoryId": "blue",
  "name": { "es": "Sombras", "en": "Shadows" },
  "activity": {
    "es": "El equipo debe...",
    "en": "The team must..."
  },
  "mode": "team"
}
```

Then run:
```bash
pnpm types:add --input tmp/new-type.json
```

### Update or remove a type
```bash
pnpm types:update --id blue_sombras --input tmp/type-patch.json --merge
pnpm types:remove --id blue_sombras
```

Note: a type cannot be removed if cards still reference it.

## Managing categories

### List categories
```bash
pnpm categories:list
```

### Add or update categories
```bash
pnpm categories:add --input tmp/new-category.json
pnpm categories:update --id purple --input tmp/category-patch.json --merge
```

### Remove a category
```bash
pnpm categories:remove --id purple
```

Note: a category cannot be removed if types still reference it.

## Managing group sets
Group sets are curated combinations of group tags for quick play.

### List sets
```bash
pnpm sets:list
```

### Add a set
Create `tmp/new-set.json`:
```json
{
  "id": "colombia-urbano",
  "groups": ["colombia", "urbano"],
  "label": { "es": "Colombia urbano", "en": "Colombia urban" }
}
```

Then run:
```bash
pnpm sets:add --input tmp/new-set.json
```

### Update or remove a set
```bash
pnpm sets:update --id colombia-urbano --input tmp/set-patch.json --merge
pnpm sets:remove --id colombia-urbano
```

## Translation workflow
- Add cards in one language first if needed.
- Use `pnpm cards:missing --language en` to find gaps.
- Provide translated `content` blocks and `answer` for the target language.
- Update `languages` to include the new language code.

## AI prompt
Use `docs/ai-card-prompt.md` when generating new cards with AI.

## ID conventions
- Categories: color name (e.g. `blue`).
- Types: `color_slug` (e.g. `blue_dibu_ciego`).
- Cards: `type_slug_###` (e.g. `blue_dibu_ciego_010`).

## Troubleshooting
- If the CLI says a type or category is unknown, create it first.
- If the CLI rejects a card, check required fields and JSON syntax.
